# 📚 书源工坊 · BookSource Studio

> 零基础也能做"阅读"App 书源的可视化工具。
> 不用懂代码——打开网页，**照着提示点几下**，或者**让 AI 替你做**，书源就做好了。

纯前端单文件应用，无依赖、无后端、不收集任何数据。手机浏览器直接打开就能用。

---

## 这是什么

[阅读](https://github.com/gedoor/legado)（Legado / 开源阅读 3.0）是一款流行的开源小说阅读器，它通过「书源」决定去哪个网站搜书、怎么找章节和正文。官方的规则语法对新手并不友好：要理解 CSS 选择器、`@text`、`{{key}}` 这些概念。

**书源工坊有两种做法：**

```
传统方式              手动点选（书源工坊）              AI 自动制作（🤖）
─────────            ─────────────────               ─────────────
研究 HTML 结构        ① 粘贴网站首页                   ① 填一次 API（OpenAI 兼容）
手写选择器            ② 粘贴一次搜索结果页网址          ② 输入网站网址
反复试错              ③ 对着网页点：这是书、这是书名…    ③ 点「开始自动制作」
失败后逐条排查         ④ 一键全链路测试 + 导出           ④ AI 自己看网页→写规则→验证→导入 App
```

## 功能特性

- **🤖 AI 自动制作**：填入任意 OpenAI 兼容 API（官方 / 中转站 / DeepSeek / Kimi…），输入网址，AI 自动分析首页找出搜索接口（含 POST 表单）、生成全部规则，**每条规则在本机用内置规则引擎验证命中数**，不对就带着错误自动重试；顺手把「发现」分类也配好
- **🪄 八步向导**：每一步只有一句话说明 + 一个动作，照着点就行
- **👆 可视化点选**：把目标网页原样打开（iframe 渲染），你点哪里，工具就自动生成哪里的规则；点书名会**顺带把详情链接也填好**
- **🧠 智能识别**：点中"一本书"或"一个章节"时自动猜出整个列表（命中几个、对不对，一目了然）；点正文段落会自动上提到整个正文容器
- **🧭 分类「发现」页**：一键扫描网站分类入口（玄幻/都市/历史…），勾选后自动生成 `exploreUrl`；再对着分类页点几下，就能在阅读 App 底部「发现」里按分类翻书；还能自动识别 `?page=2`、`xx_2.html` 这类翻页网址并转成 `{{page}}`
- **🔍 全链路测试**：真实联网跑一遍 搜索 → 详情 → 目录 → 正文 → 分类，每步显示抓到的内容和字数，失败时给出人话提示和排查方向
- **🎯 规则微调页**：向导点选的结果自动落到这里，懂行的可以手工打磨，附语法速查表
- **📦 一键导出**：生成标准 Legado bookSource JSON（含 `exploreUrl` + `ruleExplore`），复制即可在阅读 App 里「从剪贴板导入」，也可下载 .json 或导出多书源合集
- **📥 导入已有书源**：粘贴/上传 JSON 反向解析，在可视化界面里继续修改
- **💾 本地书源库**：多书源草稿管理，自动保存（localStorage），关掉浏览器不丢
- **🌐 编码自适应**：自动识别 UTF-8 / GBK / Big5，老站不乱码
- **📱 手机优先**：单文件、无框架、暗色主题，手机浏览器即开即用

## 快速开始

### 方式一：直接打开

把 `index.html` 传到手机（微信文件传输助手 / 网盘都行），用浏览器打开；或部署到任意静态托管（GitHub Pages / Cloudflare Pages）后访问。

### 方式二：GitHub Pages（推荐）

1. Fork 或上传本仓库
2. 仓库 Settings → Pages → Branch 选 `main` / root → Save
3. 几十秒后访问 `https://<你的用户名>.github.io/<仓库名>/`

## AI 自动制作怎么做（🤖 AI制作 页）

填一次 API，之后每换一个网站只需贴网址。

1. **API 设置**（填一次就存本机，Key 不会上传到任何服务器）：
   - **API 地址**：任意 OpenAI 兼容接口，以 `/v1` 结尾（如 `https://api.openai.com/v1`、DeepSeek/Kimi/中转站地址）
   - **API Key**、**模型名**：填好 Key 后点「**拉取模型列表**」，再点一下模型名输入框会弹出**自绘选择面板**（可筛选、点选即填；不依赖原生 datalist，手机浏览器全兼容）；点「**测试连接**」会真实发一条消息验证（显示耗时和模型回复）。便宜快速的模型就够（做 1 个书源约 4~6 次对话）。更换 API 地址会自动清空旧模型列表
2. **输入小说站首页网址** + 测试用的书名（越常见越好，如"斗破苍穹"），点「开始自动制作」
3. AI 会依次：分析首页找搜索接口 → 真实搜一次书看结果页 → 生成搜索规则 → 打开第一本书生成详情/目录规则 → 打开第一章生成正文规则 → 识别分类生成「发现」。**每一步都会用内置规则引擎在本机验证**（列表命中几本、正文够不够长），不合格会带着错误自动让 AI 重做
4. 完成后点「去测试」跑一遍全链路，再「去导出」

几点说明：

- **POST 搜索站**（搜什么书网址都不变）：AI 能自动识别并生成 Legado 的 POST 搜索地址；但浏览器无法预演搜索结果页，搜索页的取书规则需要回向导手动点选（或在 App 里直接验证）
- **浏览器直连报跨域**：部分 API 不允许网页直接调用，在「API 请求代理」里填一个代理即可——用本仓库 `worker.js` 部署的 Worker 就支持（已支持 POST 转发）；也支持 `{url}` 占位符写法
- API 费用极低：整个流程发送的是压缩后的网页文本，一次完整制作通常只有几分钱

## 八步向导怎么做

| 步骤 | 你要做的 | 说明 |
|------|----------|------|
| 1 网站 | 粘贴小说站首页网址 | 名字随便起 |
| 2 搜书 | 在网站里搜一本书，把**结果页网址**贴回来 | 工具自动把关键词替换成 `{{key}}` |
| 3 搜索页 | 打开网页后点 4 下：书的整块 → 书名 → 书名/封面（取链接）→ 作者 | 点错可重试 |
| 4 详情 | 工具自动打开第一本书，点书名 / 作者 / 封面 | 可跳过 |
| 5 目录 | 随便点一个章节 | 工具自动认出整份目录 |
| 6 正文 | 点一下正文文字 | 关键规则，点准就能看 |
| 7 发现 | 扫描分类 → 勾选 → 对着分类页点几下 | 可跳过，不影响搜书 |
| 8 完成 | 跑测试 → 导出 | 全程约 15 秒 |

## 「发现」分类页怎么做（第 7 步）

做完这步，阅读 App 底部会多一个「发现」入口，能像逛应用商店一样按分类翻书。

1. **点「自动扫描」**：工具去网站首页（必要时连「全部分类」页）把像分类的链接找出来，列成一排标签
2. **点标签勾选**想要的分类（默认勾了常见分类，最多 12 个；也可以「手动加一个分类」——填名字 + 网址）
3. **点「打开分类页，开始点」**：工具打开第一个分类的页面，照着点 3 下：书的整块 → 书名 → 作者/封面

几个细节：

- 扫描出的网址若带页码（如 `?page=2`、`/sort/1_2.html`），会自动改写成 `{{page}}`，App 里就能一直往下翻
- 生成的分类清单在规则页 → 「发现」里可以直接编辑，格式为每行一条 `分类名::网址`
- 不配「发现」也完全不影响搜索；导出时工具会提醒你

## 网络说明（重要）

浏览器有同源策略，网页版工具必须通过**代理**才能抓取目标网站。工具内置了几个公共免费代理并自动轮换，但公共代理**经常被限速**，能不能用全看运气。三个解决途径（按推荐程度）：

### ① 自建代理（推荐，3 分钟，永久稳定）

利用 Cloudflare Workers 的免费额度（10 万次请求/天）：

1. 注册/登录 [dash.cloudflare.com](https://dash.cloudflare.com)
2. 左侧菜单 → **Workers 和 Pages** → **创建** → 选 **"Hello World"** 模板 → 部署
3. 点 **编辑代码**，删光默认内容，把本仓库 `worker.js` 的内容**整段粘贴**进去 → **部署**
4. 复制地址栏显示的 `https://你起的名字.你的子域.workers.dev`
5. 回到书源工坊 → 向导第 1 步 → 展开「网络设置」→ 填入：
   ```
   https://你起的名字.你的子域.workers.dev/?url=
   ```

完成。此后抓取全部走你自己的代理，稳定且不限速。

### ② 手动粘贴网页（不联网也能做）

代理全挂时的保底方案，点选功能完全一样：

- **电脑**：打开目标网页 → `Ctrl+U` 看源码 → `Ctrl+A` 全选 → `Ctrl+C` 复制 → 在点选器的错误页点「手动粘贴网页」粘进去
- **文件**：把网页另存为 `.html` 后，在弹窗右上角「选文件」导入

### ③ 换网络 / 换代理

向导第 1 步「网络设置」里可一键测试所有通道的连通性；失败页也有「换个代理」按钮。

## 导入到阅读 App

1. 导出页点「复制书源」
2. 打开阅读（Legado）→ **我的** → **书源管理**
3. 右上角 **⋮** → **新建书源** → 再点 **⋮** → **从剪贴板导入**
4. 或使用「本地导入」选择下载好的 `.json` 文件（也支持导入书源合集）

## 常见问题

<details>
<summary><b>搜不同的书，网址完全不变（如 /s.php）</b></summary>

这是 <b>POST 搜索</b>：关键词不在网址里。向导第 2 步点「自动生成搜索地址」，工具会自动去网站首页分析搜索框并生成 POST 格式（Legado 写法 `s.php,{"method":"POST","body":"searchkey={{key}}"}`）。识别失败时展开「搜不同的书，网址完全不变？」手动填参数名（常见：`searchkey` / `keyword` / `keyboard`）。

注意：POST 站点在网页版测试里「搜索书籍」一步可能拿不到结果（浏览器无法直接提交 POST），书源本身在 App 里通常能用，导出后到 App 验证即可。做搜索页点选时如果打开是空页，用「手动粘贴网页」把电脑浏览器里的结果页源码贴进来。
</details>

<details>
<summary><b>测试时"搜索书籍"失败</b></summary>

- 检查搜索地址里有没有 `{{key}}`
- 有些站点需要登录才能搜索
- 部分站点用 GBK 编码关键词，而浏览器只能按 UTF-8 编码 —— 此时直接用你粘贴过的真实结果页网址即可（工具会优先使用它）
</details>

<details>
<summary><b>目录抓到了但只有几十条</b></summary>

目录分页的站点需要填「目录下一页」规则（规则页 → 目录），阅读 App 会自动翻页。
</details>

<details>
<summary><b>正文有广告 / 站点声明</b></summary>

规则页 → 正文 → 「净化正则」，格式 `要删的正则##替换成什么`，每行一条。
</details>

<details>
<summary><b>「发现」里翻不出书 / 测试第 5 项失败</b></summary>

- 分类页网址贴错了（用浏览器先确认这个网址打开后确实是一排书）
- 第一个分类正好没有书——换一个分类排在清单最前面
- 分类页的排版和搜索页不一样时，要单独对分类页做一次点选（两者规则互不通用）
</details>

<details>
<summary><b>点选时网页显示错乱</b></summary>

点选器里禁用了目标站的脚本（防止跳转），样式可能略有出入，但 DOM 结构与真实页面一致，不影响生成规则。
</details>

<details>
<summary><b>数据会丢失吗</b></summary>

书源草稿保存在浏览器 localStorage 里，清浏览器数据前请先「下载合集」备份。换设备用「导入」迁移。
</details>

## 技术说明

- **单文件**：全部 HTML/CSS/JS 在 `index.html` 内，零依赖、零构建
- **规则引擎**：浏览器内模拟 Legado 的 Jsoup 规则——`class./id./tag.` 转换、`@text/@html/@href` 属性链、`.0`/`!-1` 索引、`||` 兜底、`:regex` 截取、JSONPath；JS 规则需到 App 内验证
- **选择器生成**：从被点元素向祖先回溯，由短到长验证唯一性，产出最短可用规则；列表项字段自动生成**相对列表容器**的规则，保证导入 App 后可用
- **编码**：按响应字节流检测 `<meta charset>`，GBK/Big5 自动转码
- **隐私**：不采集、不上传；书源数据只存在你的浏览器里
